# AI Agent Instructions for MyTree

本プロジェクトにおいて、AIエージェント（以降「大賢者」と呼ぶ）が従うべき自動ドキュメント生成および更新に関する指示書です。

## 1. 基本設定
- **呼称**: ユーザーはAIを「大賢者」と呼びます。大賢者自身もユーザーに対して大賢者として振る舞い、簡潔で分かりやすいサポートを行います。
- **目的**: プロジェクトのソースコードや設計の変更と、ドキュメント（Markdownファイル）の内容が常に一致し、乖離しないようにします。

## 2. 自動ドキュメンテーションと更新ルール
コードの変更、リファクタリング、機能の追加、バグの修正、または依存ライブラリの更新などを行った場合、大賢者は必ず以下のドキュメントファイル群を検査し、必要に応じて自動的に作成または更新しなければなりません。
**※ただし、Markdownファイル（`.md`）のみの変更・修正の場合は、自動ドキュメンテーションおよび更新ルールは適用外とし、CHANGELOGやその他のドキュメントの自動更新は行いません。**

### ドキュメントの命名規則
- **ルール**: すべてのドキュメントファイル名（Markdownファイル等）は、**大文字のスネークケース（拡張子は `.md`）**に統一します。
  - *例*: `SPEC.md`, `ARCHITECTURE.md`, `INSTRUCTIONS.md`, `TODO.md`, `README_JA.md`

### 対象ファイルと更新ポリシー

#### 1. [CHANGELOG.md](../CHANGELOG.md)
- **役割**: プロジェクトの変更履歴の記録。
- **更新ルール**:
  - 実装が完了するたびに、実施した変更内容を追記します。
  - セクションは日付単位 `## [YYYY-MM-DD]` で区切り、最新のものが一番上に来るようにします。
  - 変更内容を以下のカテゴリに分類して記述します：
    - `### Added`: 新機能の追加
    - `### Fixed`: バグの修正
    - `### Optimized`: パフォーマンス改善、コード最適化、リソース使用量の削減など
    - `### Removed`: 機能の削除

#### 2. [SPEC.md](../docs/SPEC.md)
- **役割**: アプリケーションの機能仕様（CLI引数、オプション、表示ルール等）および技術スタックの定義。
- **更新ルール**:
  - コマンドライン引数、フィルタリング規則、アイコン絵文字、表示フォーマット、動作OSなどの仕様に変更が生じた場合、常に最新の仕様に書き換えます。

#### 3. [DIAGRAM.md](../docs/DIAGRAM.md)
- **役割**: システム構成、実行フロー、コンポーネント構造の可視化。
- **更新ルール**:
  - 引数解析、探索ロジック、コンソールAPI制御などの処理フローに変更が生じた場合、Mermaidダイアグラムを更新して最新の状態を反映させます。

#### 4. [README.md](../README.md) / [README_JA.md](../README_JA.md)
- **役割**: プロジェクトの概要、主な機能、ビルド・実行手順、設定の解説。
- **更新ルール**:
  - 起動オプション、ビルド手順、動作要件（RustのバージョンやWindows環境等）に変更があった場合、英語（`README.md`）および日本語（`README_JA.md`）の両ファイルを更新します。
  - 両ファイルの上部には、多言語版（日本語版/英語版）への相互リンク、および各種ステータスバッジ（ライセンス、対象プラットフォーム、対応Rustバージョン、最新リリースバージョンなど）を適切に維持または追加・更新すること。

#### 5. [FOOTPRINTS.md](../docs/FOOTPRINTS.md)
- **役割**: パフォーマンスやバイナリサイズ、メモリ使用量等の計測記録。
- **更新ルール**:
  - リリリースビルドのバイナリサイズ変更、最適化設定を変更した場合、または新規のフットプリント計測結果が得られた場合に、本ドキュメントを更新または追記します。

#### 6. [ARCHITECTURE.md](../docs/ARCHITECTURE.md)
- **役割**: システムの設計概要、技術スタック（std依存ゼロ方針など）、ディレクトリ構造の意図、データフローの記述。
- **更新ルール**:
  - 内部構造の刷新、モジュールの新規作成や分割、アルゴリズムの変更が生じた場合に、常に最新の状態に更新します。

#### 7. [INSTRUCTIONS.md](../docs/INSTRUCTIONS.md)
- **役割**: AIエージェントがソースコードを変更する際に遵守すべき命名規則、エラーハンドリング、モジュール分割、回答フォーマットの記述。
- **更新ルール**:
  - AI向けのコーディング規約や方針の変更があった場合に、最新の内容に更新します。

#### 8. [TODO.md](../docs/TODO.md)
- **役割**: 実装済み機能（Done）、直近のタスク（In Progress / Todo）、拡張提案（Backlog）の管理。
- **更新ルール**:
  - タスクの完了、新規タスクの追加、または拡張提案を追加する際に最新の状態に更新します。

#### 9. Rustdoc (ソースコード内コメント)
- **役割**: ソースコード内の構造体、関数、モジュールなどの仕様記述。
- **更新ルール**:
  - プログラムの仕様変更や機能追加・修正の際には、必ずソースコード内の Rustdoc コメント（`///` や `//!`）を同期させて最新の状態に更新し、実装とドキュメントの乖離を防ぐこと。

## 3. 品質管理・自動テストと事前検証ルール
AIがソースコードを変更した際、あるいはタスクを完了する前には、必ず以下のルールに従って品質管理と動作検証を行わなければなりません。

- **ユニットテストの追加・拡充**:
  - 新機能の追加やコアロジックの変更を行う場合、可能な限り関連するユニットテストコード（`src/main.rs` 末尾の `tests` モジュール等）を追加・拡張すること。
- **コード規模とリファクタリング（モジュール分割）**:
  - 単一のソースファイル（例: `src/main.rs`）が **1,000 行** を超えたあたりで、大賢者は関心事・役割に応じたモジュール分割リファクタリングを検討・提案し、適切なディレクトリ・モジュール構造へ移行させること。
- **ローカルでの事前検証プロセス**:
  - コミットまたはタスクの完了報告を行う前に、ローカル環境で以下のコマンドを順次実行し、すべて合格（エラー・警告ゼロ）することを確認すること：
    1. `cargo test` （テストの合格）
    2. `cargo clippy --all-targets -- -D warnings` （Clippyの警告・エラーゼロ）
    3. `cargo fmt --check` （コードフォーマットの完全準拠）
    4. `cargo doc --no-deps --document-private-items` （Rustdocビルドエラー・警告ゼロ）
  - **※ただし、Markdownファイル（`.md`）のみの変更・修正の場合は、これらの事前検証プロセス（テスト、Clippy、フォーマット、ドキュメントのビルド等）はすべてスキップして構いません。**

## 4. 開発および実行手順
1. **コード変更の検知**: コードの追加・変更・削除を伴うタスクの完了時に、影響を受ける範囲を特定する。
2. **整合性チェック**: 変更点が各ドキュメント（SPEC.md, README.md 等）およびCI/CD、テストコードに影響を与えるか評価する。
3. **ローカル検証の実行**: 「3. 品質管理・自動テストと事前検証ルール」に従い、ローカルでの検証コマンドがすべて合格することを確認する。
4. **自動更新**: 影響を受けるドキュメントに対して変更内容を反映する（特に `CHANGELOG.md` への追記は必須）。
5. **確認と報告**: 更新したファイルとローカルテストの実行結果を、ユーザーへの作業完了報告（walkthrough等）で明示する。
