# テスト方針・実行ガイド (TESTING.md) - MyTree

[English](../en/TESTING.md) | **日本語版**

本文書は、`MyTree` プロジェクトにおけるユニットテスト、結合テスト、および品質検証に関する方針と実行手順をまとめたドキュメントです。

---

## 1. テスト概要

`MyTree` は標準ライブラリ（`std`）のみで構築された超軽量 CLI ツールであり、信頼性と堅牢性を維持するために包括的なテストを実施します。

主要なテスト観点：
- **引数解析・設定読み込み**: CLIオプションの適切なパースと競合チェック
- **パスフィルタリング**: ワイルドカード (`*`, `?`) や `.gitignore` パターンの正当性
- **ツリー構築・深さ制限**: ディレクトリ構造の巡回および深さ制御
- **フォーマット出力**: テキスト、クラシック、JSON、XML各形式のエンコード出力
- **クロスプラットフォーム動作**: Windows、Linux、macOSにおける文字エンコーディングとパス区切り処理

---

## 2. テストの実行手順

ローカル環境でのテスト実行手順は以下の通りです。

### ユニットテストの実行
```bash
cargo test
```

### 特定のテストケースのみ実行
```bash
cargo test test_parse_arguments
```

### 品質・コード検証コマンド
コード変更完了時には、以下の標準コマンドが全てエラー・警告なしで合格することを確認します：

```bash
# 1. ユニットテスト実行
cargo test

# 2. 静的解析 (Clippy)
cargo clippy --all-targets -- -D warnings

# 3. コードフォーマット検証
cargo fmt --check

# 4. Rustdoc ビルド検証
cargo doc --no-deps --document-private-items
```

---

## 3. テストの記述ガイドライン

1. **モジュール内テスト**:
   - 各モジュールの末尾に `#[cfg(test)] mod tests` を配置し、非公開関数や内部ロジックをテストします。
2. **パニック回避のテスト**:
   - 不正な入力（存在しないパス、壊れた引数等）に対してもパニックせず適切な `Err` またはデフォルト動作を返すことをテストします。
3. **OS依存テストの条件分岐**:
   - Windows固有処理やUnix固有処理には `#[cfg(windows)]` または `#[cfg(not(windows))]` 属性を付与します。
