# AI Development Instructions (INSTRUCTIONS.md) - MyTree

[English](../en/INSTRUCTIONS.md) | **日本語版**

本文書は、AIエージェント（大賢者）が `MyTree` のソースコードを変更・保守・機能追加する際に遵守すべきガイドラインおよび開発規約です。

---

## 1. 開発原則

1. **外部依存ゼロ (Zero External Dependencies) の厳守**:
   - `Cargo.toml` の `[dependencies]` にサードパーティクレートを追加してはなりません。常に Rust 標準ライブラリ (`std`) の機能を優先して活用してください。
2. **クロスプラットフォーム互換性**:
   - Windows 固有の処理 (`Win32 API` や `#[cfg(windows)]`) を追加する場合は、Linux/macOS 環境でビルドエラーにならないよう条件付きコンパイルを徹底してください。
3. **Rustdoc コメントの維持・同期**:
   - 新しい関数、構造体、モジュール、フィールドを追加した場合は、必ず `///` による Rustdoc ドキュメントコメントを記述してください。
4. **他言語開発経験者に配慮した解説方針**:
   - ユーザーは他言語での開発経験をお持ちですが、Rust / React / TypeScript 等の固有の専門用語（所有権、トレイト、フック等）には不慣れです。一般的なプログラミング概念に置き換えるか直感的な補足解説を添えて報告してください。

---

## 2. コードスタイルのガイドライン
- **フォーマット規則**: `cargo fmt` の標準スタイルに従ってください。
- **型と変数名**:
  - 構造体 / 列挙型: `PascalCase` (例: `TreeConfig`)
  - 関数 / 変数 / モジュール: `snake_case` (例: `parse_arguments`)
  - 定数: `SCREAMING_SNAKE_CASE` (例: `STD_OUTPUT_HANDLE`)
- **エラー処理**:
  - パニック (`panic!`, `unwrap()`) の使用は回避し、可能な限り `Result<T, String>` や明示的なエラーハンドリングを行ってください。

## 3. 自動ドキュメンテーションと更新ルール (モジュール化退避)
コードの変更、リファクタリング、機能追加、バグ修正、依存ライブラリ更新時は、関連ドキュメントを**英語版（`docs/en/`）と日本語版（`docs/ja/`）の双方で同時更新・完全同期**します。
**※ただし、Markdownファイル（`.md`）のみの変更・修正の場合は、自動ドキュメント更新および検証プロセスはスキップします。**

| ドキュメント                     | 役割                   | 更新トリガー・ルール                                                                                  |
| :------------------------------- | :--------------------- | :---------------------------------------------------------------------------------------------------- |
| **CHANGELOG.md**                 | 変更履歴の記録         | 実装完了ごとに追記。日付単位 (`## [YYYY-MM-DD]`)・カテゴリ別 (`Added`, `Fixed`, `Optimized`, `Removed`) に最新が上に来るよう記述。 |
| **SPEC.md**                      | 機能仕様・定義         | CLI引数、オプション、表示ルール、動作OS等の仕様変更時に更新。                                         |
| **DIAGRAM.md**                   | システム構成・可視化   | 処理フローや構造の変更時に Mermaid ダイアグラムを更新。                                               |
| **README.md** / **README_JA.md** | 概要・実行手順         | 起動オプション、ビルド手順、動作要件等の変更時にルート両ファイルを更新。                             |
| **FOOTPRINTS.md**                | パフォーマンス計測     | バイナリサイズ、メモリ使用量、ビルド最適化等の計測データ更新時に追記。                                 |
| **ARCHITECTURE.md**              | 設計・モジュール構造   | 内部構造の刷新、モジュール分割、std依存ゼロ方針などのアルゴリズム・設計変更時に更新。                 |
| **INSTRUCTIONS.md**              | AI規約・詳細ガイド     | AI向けコーディング規約や詳細方針の管理。                                                              |
| **TODO.md**                      | タスク管理             | タスク完了 (Done)、進行中 (In Progress/Todo)、拡張提案 (Backlog) の変更時に更新。                     |
| **TESTING.md**                   | テスト方針・ガイド     | テスト観点、検証手順、コマンド・パッチ変更時に更新。                                                 |
| **RELEASE.md**                   | リリース手順書         | バージョン更新、ビルド手順、タグ打ち手順の変更時に更新。                                             |
| **CONTRIBUTING.md**              | 貢献者ガイド           | PR手順、コミット規約、環境構築手順の変更時に更新。                                                   |
| **SECURITY.md**                  | セキュリティ方針       | セキュリティ設計原則、サポートバージョン、脆弱性報告先の変更時に更新。                               |
| **Rustdoc** (ソース内コメント)   | コード仕様記述         | 構造体・関数・モジュール等の仕様変更時に `///` や `//!` を同期更新。                                  |

## 4. 品質管理・自動テストと事前検証ルール (モジュール化退避)
- **1,000 行制限ルール**:
  - 単一のプログラムソースファイル（例: `src/main.rs`）が **1,000 行** を超えたあたりで、関心事・役割に応じたモジュール分割を提案・実施。
- **ローカル事前検証**:
  *(※Markdownファイル（`.md`）のみの変更時は、以下のローカル事前検証を省略して迅速に対応する)*
  1. `cargo test`
  2. `cargo clippy --all-targets -- -D warnings`
  3. `cargo fmt --check`
  4. `cargo doc --no-deps --document-private-items`
